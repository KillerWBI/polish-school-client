# Frontend — Прогресс разработки

## 🔧 Ревью + правки интерфейса (2026-08-01)

**Подсказка больше не ломает вёрстку.** `Tooltip` рисовал облачко абсолютом внутри родителя. Если родитель со скроллом (а `Tabs` — именно такой, `overflow-x-auto`), облачко раздувало его: браузер показывал полосы прокрутки по обеим осям (`overflow-x:auto` превращает `overflow-y:visible` в `auto`) — при наведении на вкладку «выезжало пустое поле». Теперь облачко рисуется **порталом в `body` с `position:fixed`**, координаты берутся из `getBoundingClientRect` анкера, при скролле/ресайзе подсказка прячется (координаты посчитаны один раз). Попутно `Tabs` получил `scrollbar-none` — на узком экране лента вкладок прокручивается без системной полосы, которая на Windows съедала высоту. Правка общая: чинит подсказки во **всех** контейнерах со скроллом.

**Создание ДЗ — сначала группа, потом её урок.** Было: один список всех уроков учителя (и он же обрезан лимитом 50 с сервера) — при десятках групп нужный урок было не найти. Стало: **два шага** — выбор группы, затем урок; список уроков грузится **только выбранной группы** (`getLessons({ groupId })`, серверный фильтр уже был), до выбора группы второй список заблокирован, смена группы сбрасывает урок, для группы без уроков — понятная подсказка. `HomeworkPage.jsx:CreateHWModal`. Новые ключи в 4 языках: `homework.groupLabel/chooseGroup/chooseGroupFirst/noLessonsInGroup`.

**Найдено ревью и закрыто:**
- **XSS через ссылку урока.** `lessonLink`/`chatLink` — свободный текст учителя; `safeUrl()` применялся не везде. Без обёртки были `CalendarPage` (ссылка на урок и на чат группы), `IndividualLessonsPage`, `IndividualCourseDetailPage` — учитель мог вписать `javascript:…`, и код исполнялся в сессии ученика, открывшего календарь. Теперь ссылка пропускается только со схемой http/https, иначе кнопка не рисуется.
- **`VerifyEmailPage`** — единственная auth-страница мимо общего `AuthLayout`, с синим квадратом и буквой **«L»** от старого бренда LinguaFlow (ребрендинг в Diklario её пропустил). Переведена на общий каркас, ключ `auth.verifyPanelTitle` в 4 языках.
- Мёртвые импорты: `Input` (`HomeworkPage`), `formatDate` (`IndividualLessonsPage`), `MoreHorizontal` (`DashboardPage`).
- `MonthArrow` вынесен из тела `MonthNav` (`AttendancePage`) — объявленный внутри рендера, он пересоздавался и обе кнопки перемонтировались вместо обновления.

**Осталось из ревью:** эмодзи, пережившие фазу 0, в 13 боевых экранах (`GroupDetailPage`, `CalendarPage`, `IndividualCoursesPage`, `HomeworkPage`, `PaymentsPage`, `HelpPage`, `TopicDetailPage`, `QuizRunner`, `DailySessionPage`, `CardReview`, `IdeasModal`, `TeacherCharts`, `ErrorBoundary`) — отдельным проходом. Фронт по-прежнему без тестов.

### Фаза 1 — навигация ✅
- **Сайдбар распластан**: без скруглений и рамок, во всю высоту, прижат к краю экрана.
- **Свёрнут до иконок**, разворачивается по наведению **поверх** контента — страница не дёргается. В мобильной шторке всегда развёрнут (`collapsible={false}`).
- **Пользователь больше не дублируется**: в сайдбаре только аватар, имя и роль — единственный раз в меню профиля.

- **Разделы объединены**: учитель — Группы + Индивидуальные курсы → **`/lessons` «Занятия»** (10 → 9 пунктов); ученик — Заметки + Внешние занятия + Прогресс → **`/diary` «Мой дневник»** (14 → 12). Старые адреса перенаправляются, вкладка живёт в адресе (`?tab=`).
- **«Добавить слот» → «Добавить регулярный урок»** во всех четырёх языках (`groups.addSlot`, `groupDetail.addSlot`).
- Захардкоженный русский в сайдбаре/шапке/мобильном меню переведён в i18n.

**Как сделан упор в лимит.** Бэкенд уже отдавал `code: 'PLAN_LIMIT'` с `resource` и `max` — фронт это игнорировал. Перехват поставлен в `api/client.js`, **один на все десять мест**, где лимит может сработать (группы, ученики, курсы, треки, словарь, заметки). Текст собирается на фронте из `resource`+`max`, поэтому он переведён, а не приходит русским с сервера. Чтобы вызывающий код не показал второй тост поверх первого, ошибка помечается `planLimitShown`, а `errMsg` для неё возвращает пустоту (`toast.error('')` ничего не делает).

Заодно вынесен в i18n хардкод-русский, попавший под руку: тосты оплаты и строка «≈ из $…» в `PlansPage`, «Нет связи с сервером» и «Ошибка сервера» в `api/client.js`.

## 👤 Ученик без преподавателей на платформе (2026-07-30)

Ученик, который занимается офлайн или сам, раньше упирался в две вещи: преподавателя и предмет приходилось **вписывать строкой заново при каждой записи** (поэтому «Пан Войтек» и «пан войтек» становились разными людьми, а вести долг по конкретному человеку было нельзя), и эти занятия **не попадали в календарь** — их можно было найти только вкладкой в дневнике.

**«Мои преподаватели»** — карточки, которые ученик заводит сам: имя, предмет, цена за занятие, контакт. Зеркало ученика без аккаунта у преподавателя: тому, кого завели, ничего не приходит, записи ведёт владелец карточки. Вкладка «Преподаватели» в `/diary?tab=lessons` — список + «+» → модалка, как везде после фазы 3. У каждой карточки видно число занятий и долг.

**Создание занятия переделано:** преподаватель выбирается из заведённых карточек (а не вписывается), предмет и цена **подставляются из карточки** и правятся для конкретного занятия; предмет вдобавок подсказывает уже введённые значения через `datalist` — новое название по-прежнему можно ввести. Карточку можно завести прямо из формы занятия. Галочка **«Повторять еженедельно»** создаёт 3 занятия по неделям; каждое — отдельная запись, лишнее удаляется по одному.

**Учитывается наравне с платформенными занятиями:**

| Где | Что видно |
|---|---|
| `/calendar` | свои занятия отдельным цветом (бирюзовый) + в легенде; клик → детали (преподаватель, длительность, цена и оплата, заметки) и ссылка в дневник. Без времени — событие на весь день |
| `/dashboard` | входят в «занятий на неделе» и в блок ближайших занятий |
| `/payments` | блок «Мои преподаватели» с долгом по каждому и пометкой, что оплата идёт мимо платформы |
| `/my-progress` | в streak, карте активности и часах — **только прошедшие**: план на три недели вперёд не должен накручивать серию |

**Бэкенд:** модель `StudentTeacher` + CRUD `/student-teachers` (в списке сразу сводка `lessons`/`debt`); `StudentLessonLog.studentTeacherId` со ссылкой на карточку — имя дублируется в `teacherLabel`, поэтому удаление карточки не стирает историю (`ON DELETE SET NULL`). Переименование карточки обновляет подпись в её занятиях. Из `GET /my-lessons/stats` убрана разбивка `byTeacher` — она считалась по строке-имени, теперь приходит из `/student-teachers` по карточкам. ⚠️ **Прод-миграция `20260730000001-student-teachers`.**

### Поиск в шапке — удалён ✅
Искал только группы и учеников. И то и другое — один клик через меню, а на странице «Ученики» есть свой поиск: чистое дублирование. Вдобавок развёрнутый сайдбар накрывал его краем, и поле выглядело сломанным. Убран на десктопе и в мобильной шапке вместе с осиротевшими ключами `topbar.search*`. Левая часть шапки теперь намеренно пустая — её накрывает сайдбар, и держать там что-то интерактивное нельзя.

### Карточка ученика ✅
- Новый эндпоинт **`GET /students/:id/overview`** — группы, индивидуальные курсы, посещаемость (всего/был/процент), задания (выдано/сдано/оценено/средняя), деньги (начислено/оплачено/долг). **Граница жёсткая:** `:id` — это `Student.id`, уже привязанный к `teacherId`, поэтому занятия ученика у других преподавателей не попадают в выборку. Задания считаются только по группам, где ученик состоит, и по его индивидуальным урокам.
- Кнопка «Открыть карточку» на карточке ученика → большая модалка со всем перечисленным и пометкой, что показаны только занятия с этим преподавателем.
- Расчёт денег переиспользует `fetchChargesAndPayments` из `payment.controller` (теперь экспортируется) — единый источник истины по долгу.

### Объяснение «откуда берутся ученики» ✅
